# backend

このディレクトリには、バックエンドアプリケーションのソースコードと関連ファイルが含まれています。

## 概要

バックエンドアプリケーションは、NestJS フレームワークを使用して構築されており、Prisma ORM を利用して PostgreSQL データベースと連携しています。主な機能として、ユーザー認証、ノートの管理（作成、編集、削除）などがあります。

## 簡単な説明

**NestJS** は、TypeScript をベースとした進化的な Node.js フレームワークであり、 **モジュールベース** のアーキテクチャを採用しています。

1つの機能は1つのモジュールとしてまとめられています。例えば、認証に関する機能は `auth` モジュールに、ノート管理に関する機能は `note` モジュールに分かれています。

さまざまなファイルがありますが、主に使うのは「controller」「service」「module」です。

主に [src](./src) ディレクトリ内に以下のように配置されています。

- **Controller**: クライアントからのリクエストを受け取り、適切なサービスに処理を委譲します。ルーティングもここで定義されます。
- **Service**: ビジネスロジックを実装し、データベースとのやり取りを行います。具体的な処理はここで行われます。
- **Module**: 関連するコントローラーとサービスをまとめ、アプリケーションの構成要素を整理します。簡単に言うと、「このモジュールはこのファイルを使うよ」と宣言する場所であり、依存関係の注入もここで設定されます。

なお、 [domain](./src/domain) ディレクトリには、DBに定義されたエンティティに対する処理を行う関数がまとめられています。  
DBとのやり取りを直接担当する処理を「repository」というファイルにさらに分割することで、 **サービス層がビジネスロジックのみを担当できる** ようにしました。これはクリーンアーキテクチャの考え方に基づいています。

---

Prismaは、ORMツールであり、TypeScript/JavaScriptアプリケーションとデータベース間のやり取りを簡素化します。Prismaを使用することで、SQLクエリを直接書くことなく、型安全な方法でデータベース操作が可能になります。
Prismaは大きく以下の機能を提供します。

- **Prisma Client**: 自動生成される型安全なクエリビルダーです。データベース操作を簡単に行えます。
- **Prisma Migrate**: データベーススキーマのバージョン管理とマイグレーションをサポートします。
- **Prisma Studio**: データベースの内容を視覚的に確認・操作できるGUIツールです。

Prismaを利用するときは、まず [schema.prisma](./prisma/schema.prisma) ファイルでデータモデルを定義します。

これはデータテーブルの設計図のようなもので、各モデルはデータベース内のテーブルに対応し、モデルのフィールドはテーブルのカラムに対応します。

この定義をもとに、migrateによって接続先のデータベースにテーブルが作成されます。
その後、Prisma Clientを生成し、アプリケーションコード内でTypeScriptの型として利用できます。

Prismaは最近 v7 に更新されました。これは **破壊的変更を伴うメジャーアップデート** であるため、環境構築のために公式ドキュメントを参照して対応しました。
